# Дневник давления

Личный трекер артериального давления и пульса. Сайт живёт на GitHub Pages,
а записи хранятся в этом же репозитории, в файле
[`data/readings.json`](data/readings.json). Каждое добавленное или удалённое
измерение становится коммитом в ветку `main`. Своего сервера и сторонних
сервисов нет.

## Как это работает

- Страница читает `data/readings.json` через GitHub API и показывает историю.
  Читать может кто угодно, если репозиторий публичный.
- Чтобы **сохранять** записи, сайту нужен ваш токен GitHub. Он вводится один
  раз, хранится только в браузере (localStorage) и отправляется только на
  `api.github.com`. Без токена сайт работает в режиме «только чтение».
- Пока идёт сохранение, в шапке видно «Сохранение…», после успеха
  «Сохранено · abc1234» с номером коммита.
- Если файл изменили с другого устройства, сайт перечитает его и повторит
  запись, так что два устройства не затирают друг друга.
- Записи из старой версии дневника (localStorage) после загрузки предлагается
  перенести в репозиторий.
- Экспорт и импорт истории в JSON-файл на месте.

## Настройка (один раз, около 5 минут)

### 1. Включите GitHub Pages

**Settings → Pages → Build and deployment**: Source = *Deploy from a branch*,
Branch = `main`, папка `/ (root)`. Через минуту сайт откроется по адресу
`https://ВАШ_ЛОГИН.github.io/bp-diary/`.

Владелец и имя репозитория определяются из этого адреса автоматически.
Если сайт открывается откуда-то ещё (например, с вашего компьютера как файл),
проверьте значения в [`config.js`](config.js).

### 2. Создайте токен

1. Откройте <https://github.com/settings/personal-access-tokens/new>
   (Settings → Developer settings → Personal access tokens → Fine-grained
   tokens → Generate new token).
2. **Repository access**: *Only select repositories* → выберите `bp-diary`.
3. **Permissions → Repository permissions → Contents**: *Read and write*.
   Больше ничего не включайте.
4. **Expiration**: выберите срок подольше. Когда токен истечёт, сайт покажет
   ошибку «GitHub не принял токен», и его нужно будет создать заново.
5. Нажмите **Generate token** и скопируйте его: GitHub показывает токен
   только один раз.

### 3. Подключите сайт

Откройте сайт, прокрутите до раздела **Хранение**, вставьте токен и нажмите
**Подключить**. Сайт проверит, что токен работает и даёт право на запись, и
запомнит его в этом браузере. На другом устройстве или в другом браузере
токен нужно ввести ещё раз (тот же самый подойдёт).

## Приватность

Если репозиторий публичный, файл с записями может прочитать любой, кто знает
адрес. Если это нежелательно, есть два пути:

- **Сделать репозиторий приватным.** GitHub Pages для приватных репозиториев
  доступен только на платных планах, но сайт не обязан жить на Pages: можно
  скачать `index.html` и `config.js` на компьютер и открывать `index.html`
  как файл. Чтение и запись через API с токеном будут работать, а без токена
  никто ничего не увидит.
- **Держать сайт и данные раздельно.** Сайт в публичном репозитории, а в
  `config.js` указать приватный репозиторий с данными. Токен тогда выдаётся
  на приватный репозиторий.

## Локальная проверка

```
python3 -m http.server 8000
```

и откройте <http://localhost:8000>. Значения для API берутся из `config.js`.

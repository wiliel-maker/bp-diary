# Дневник давления

Трекер артериального давления и пульса с аккаунтами, облачным хранением и
настройками приватности. Сайт статический (GitHub Pages), данные и аккаунты
живут в [Supabase](https://supabase.com) на бесплатном тарифе. Своего сервера
не нужно.

## Что есть

- **Аккаунты.** Регистрация по email и паролю, логин вида `@ivan_p`,
  восстановление пароля по ссылке из письма, смена пароля в настройках.
- **Автосохранение.** Каждое добавленное или удалённое измерение сразу
  уходит в базу. История доступна с любого устройства после входа.
- **Пользователи.** Страница со всеми зарегистрированными пользователями и
  поиском по логину или имени. У открытых дневников видно число записей и
  дату последнего измерения, дневник можно открыть и посмотреть.
- **Приватность.** Дневник по умолчанию закрыт: другие видят только логин и
  имя. В настройках его можно открыть, а также отдельно скрыть заметки.
  Правила проверяются на стороне базы (Row Level Security), а не в браузере.
- **Перенос старых записей.** Если в браузере остались записи из прежней
  версии (localStorage), после входа появится предложение перенести их в
  аккаунт.
- **Экспорт и импорт** истории в JSON-файл.

## Настройка (один раз, около 10 минут)

### 1. Создайте проект в Supabase

1. Зарегистрируйтесь на <https://supabase.com> и нажмите **New project**.
2. Укажите любое имя, придумайте пароль базы (он больше нигде не понадобится),
   выберите ближайший регион. Тариф **Free**.
3. Дождитесь, пока проект создастся (1–2 минуты).

### 2. Примените схему базы

1. В левом меню откройте **SQL Editor** → **New query**.
2. Скопируйте содержимое файла [`supabase/schema.sql`](supabase/schema.sql)
   целиком, вставьте в редактор и нажмите **Run**.
3. Должно появиться `Success. No rows returned`. Повторный запуск безопасен.

Схема создаёт таблицы `profiles` и `readings`, триггер, который заводит
профиль при регистрации, правила доступа и три функции для сайта.

### 3. Настройте вход по email

1. **Authentication → Providers → Email**: провайдер должен быть включён.
2. Там же есть переключатель **Confirm email**. Если его выключить,
   пользователи смогут входить сразу после регистрации без письма. Если
   оставить, после регистрации надо будет подтвердить адрес по ссылке из
   письма. Бесплатный тариф отправляет ограниченное число писем в час, так что
   для небольшого числа пользователей проще выключить.
3. **Authentication → URL Configuration → Site URL**: укажите адрес сайта,
   например `https://ВАШ_ЛОГИН.github.io/bp-diary/`. Сюда будут вести ссылки
   из писем подтверждения и восстановления пароля. Тот же адрес добавьте в
   **Redirect URLs**.

### 4. Вставьте ключи в `config.js`

1. Откройте **Project Settings → API**.
2. Скопируйте **Project URL** и ключ **anon public**.
3. Впишите их в файл [`config.js`](config.js):

```js
window.BP_CONFIG = {
  supabaseUrl: 'https://xxxxxxxxxxxx.supabase.co',
  supabaseAnonKey: 'eyJhbGciOi...'
};
```

Ключ `anon` рассчитан на публикацию в открытом коде: он даёт только те права,
которые разрешены правилами из `schema.sql`. Ключ `service_role` никогда не
вставляйте в сайт.

### 5. Включите GitHub Pages

**Settings → Pages → Build and deployment**: Source = *Deploy from a branch*,
Branch = `main`, папка `/ (root)`. Через минуту сайт откроется по адресу
`https://ВАШ_ЛОГИН.github.io/bp-diary/`.

Пока `config.js` не заполнен, сайт показывает предупреждение вместо формы
входа.

## Как устроена приватность

| Кто                         | Профили (логин, имя, открыт/закрыт) | Свои записи        | Чужие записи                                  |
|-----------------------------|--------------------------------------|--------------------|-----------------------------------------------|
| Не вошедший                 | нет                                  | нет                | нет                                           |
| Вошедший                    | все                                  | читать, писать, удалять | только у открытых дневников, через `diary_of` |
| Владелец закрытого дневника | —                                    | всё                | —                                             |

Функция `diary_of(username)` отдаёт чужие записи только если дневник открыт,
а заметки только если у владельца включено «Показывать заметки». Всё это
выполняется в базе, поэтому обойти из браузера нельзя.

## Локальная проверка

Откройте `index.html` через любой статический сервер, например:

```
python3 -m http.server 8000
```

и зайдите на <http://localhost:8000>. Для локальной работы добавьте
`http://localhost:8000` в **Redirect URLs** в Supabase.
